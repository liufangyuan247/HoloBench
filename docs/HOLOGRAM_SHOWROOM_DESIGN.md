# 全息干板交互式重建展示间

日期：2026-09-05。状态：完整目标持续实施中。首个单色展示间增量已实现，操作见 [使用说明](SHOWROOM_AND_LENS_DESIGN_GUIDE.md)，实际范围与验证见 [PROJECT_STATE](PROJECT_STATE.md) 和 [ADR 0044](adr/0044-detached-reflection-observer-and-profile-design.md)。本文其余部分保留完整目标；白光、RGB 合成与完整多 hogel 观察尚未完成。

## 产品目标

用户将共享 Bench 中已曝光的反射全息干板送入黑色背景的展示间。干板位于视角中心，白光或单色光源照明。鼠标拖动旋转干板，用户直接看到随观察方向和照明条件改变的重建像，包括视差、深度、亮度和颜色变化。计算量较大时允许渐进细化，操作本身保持响应。

展示间是已记录样品的观察模式。它与实验 Bench 共享记录产物和光学求解接口，不建立另一套隐藏的打印/记录物理。这里的“全息镜片”按用户描述指已记录的全息干板，不额外假设它是具有特定聚焦功能的全息光学元件（HOE）。

## 1. 默认交互

- 从选中的已记录干板进入“展示重建”；返回后仍是原 Bench。也可以直接打开独立保存的记录产物。
- 背景纯黑，默认隐藏桌面、坐标轴、光线和所有工程面板。干板居中；其边界由简洁夹框或选中轮廓提示。轮廓属于界面辅助，不向记录模型加入照明。
- 左键拖动以干板中心为枢轴做轨迹球旋转；默认光源和观察相机留在世界坐标中，不随干板旋转。限制背面或大倾角的模型不得被限制交互来伪装支持，应明确提示该观察条件未被模型覆盖。
- 滚轮移动观察距离；单独的“观察位置”操作移动/环绕相机，保持干板和灯的位置。旋转干板与移动观察者是不同实验。
- 底部只保留光源类型、亮度、重置姿态和返回；单色模式按需显示波长。光源位置/入射方向、光源角尺寸、相机焦点和瞳孔在抽屉中调整。
- 小型状态提示区分“交互预览”“正在细化”“已收敛”“模型范围外”。曝光显示范围默认锁定，避免自动提亮掩盖布拉格失配导致的变暗。
- 参考照明方向可作为一键复位设置，但切换白光后不能暗中重新朝向最亮角度。

需要看见的是观察者所接收的重建光，而不只是干板面上的强度分布。干板表面玻璃反光和重建像可同时显示，二者应独立计算并允许分别检查。

## 2. 现有基础与缺口

| 已有基础 | 当前限制 | 接入方向 |
| --- | --- | --- |
| `VolumePlateRecordingResult` 保存光栅矢量、材料、可选物光/参考光复场 | 数据绑定源 Bench revision，且采样未必足以重建 | 转为不可变记录产物，并检查其能力与采样有效域 |
| `BenchVolumeHologramReplay` 有板面出射场及到放置观察面的传播 | 受中心光栅、等效对称 Kogelnik 及采样范围限制 | 提取与原 Bench 生命周期解耦的出射场求解服务 |
| `OpticalBenchRenderer::renderObservationTexture` 显示平面纹理 | 板面强度纹理不能表达观察瞳孔选择、虚像深度及完整视差 | 新建展示间合成器，消费观察相机图像或有界方向响应缓存 |
| CHIMERA 相机使用放置的镜片处方与有限瞳孔 | 其方向样本目前仍由原视图颜色加记录效率生成 | 保留相机基础，替换为来自记录产物的出射光 |
| `BenchWaveObservationWorker` 支持后台渐进采样、取消与请求编号 | 当前请求描述的是 Bench 上的观测平面 | 复用调度机制，新增干板/光源/观察者请求状态 |

`replayVolumeReflectionToObservation` 会拒绝过期记录及未解析载波的采样。展示间不能通过改写 revision 或强行把 `carrierSampled` 置真绕过检查。数据不足时应解释需要重新记录/导出哪种证据。

## 3. 记录、姿态和观察必须分离

拟议数据边界，命名可在实现时调整：

### RecordedHologramAsset：不可变记录产物

保存介质局部坐标下的口径、厚度、材料及收缩状态、逐波长/逐 hogel 的记录响应与求解所需复数据、相干假设、采样约定、模型版本、校准与内容哈希。保存来源 Bench 信息供追溯，但重建不要求该 Bench 仍然存在。

不能只保存干板截图、输入多视图、效率系数或打印任务完成标志。CHIMERA 当前的精简批处理产物不自动等价于可独立重建的完整记录。需在能力字段中区分方向预览、单色复场重建、RGB 重建、光谱重建和可用观察角域。

### HologramInstance：展示中的实体

引用记录产物，保存刚体位置/旋转及夹框外观。改变姿态不改写记录局部数据，不重新曝光，也不使已记录介质失效。不同实例可以引用同一个记录产物。

### ReplayIllumination / Observer：重建条件

照明保存世界坐标中的光源位置或方向、光谱功率分布、空间范围、偏振与相干模式。观察者保存世界坐标、有限入口瞳孔、成像模型、焦点、曝光和光谱/显示响应。

光源、干板或观察者变化只使依赖这些条件的计算缓存失效。源文件改变与用户重新曝光才创建新的记录版本。

## 4. 光学计算链

1. 将光源与观察者转换到干板局部坐标。若干板刚体旋转为 R，局部光栅矢量 K 在世界中为 R K；不能只旋转显示网格而保留原照明角度。
2. 根据真实入射场、波长、角度和材料状态，计算布拉格选择及衍射出射场/有界角分布。沿用项目约定的 `K = k_object - k_reference`，通过独立重建方向基准验证符号与反射侧。
3. 将出射光传播到观察者入口瞳孔，应用有限口径和成像光学，计算相机/眼模型的像面。每个像素反映到达该观察系统的光；板面出射强度本身不是最终图像。
4. 同一相干模式内先加复振幅再取强度；不同非相干照明模式和波长按强度加权。跨 hogel 的相干关系必须来自记录模型，不能为了避免散斑随意改成非相干叠加。
5. 转换为显示颜色，并与板/夹框的可见表面合成。波长积分、颜色转换与显示曝光分开。虚像、实像的可见位置来自传播及成像关系，不另放一个原始 3D 物体充当重建结果。

物理求解属于 `optics/`，CPU/GPU 数值实现属于 `compute/`；展示用 shader 属于 `render/`。GPU compute shader 可以执行已定义模型，但需要相同模型的 CPU 参考及数值对照，不能由外观 shader 私自定义布拉格颜色或效率。

## 5. Shader 与加速策略

### 即时交互

干板的刚体变换、夹框、黑背景和已有结果合成走普通 GPU 渲染。计算较慢时继续响应鼠标。已有结果只能在经过验证的邻近姿态范围内做方向插值/重投影，且标为预览；不能把旧像固定贴在旋转后的板上并宣称当前光学结果。

### 后台细化

按像面分辨率、瞳孔采样、光谱/光源模式数逐步增加计算。初始可试 128 → 256 → 512 的像面分辨率，但记录数据、FFT 网格及带宽不能任意降采样；每阶段须保持其声明域内的采样有效性。无法满足时输出受限预览，不把混叠当物理细节。

采用 latest-request-wins：新拖动取消旧任务；结果带完整请求键，主线程只接收当前条件的结果。旋转、换灯、观察变化时清除不兼容的渐进累积，避免拖影和过期帧覆盖新结果。

### 分层缓存

- 记录产物及材料响应可长期缓存，受内容哈希与模型版本约束。
- 出射场缓存依赖干板相对光源姿态、照明模式和波长。只移动相机通常可复用。
- 相机结果依赖观察位置、瞳孔、焦点、采样和出射场版本。
- CHIMERA 可分块加载 hogel，并在已验证条件内对角度响应插值；需要处理孔径遮挡、视域边缘、方向混叠及相干相位，不能无限外推。
- 不预计算全部“干板角度 × 灯角度 × 眼位置 × 波长”组合。此状态空间太大，应按当前观察条件懒加载并限制内存。

当性能受限时先减少独立照明模式或观察分辨率，并明确当前误差/进度；不能省略导致像出现或消失的物理因素而不标识。GPU 能力与回退继续按运行时探针决定。

## 6. 单色与白光分别验收

第一阶段先实现已记录单色反射干板＋窄带照明＋有限瞳孔观察。先验证转动引起的布拉格失配、可见视域和视差，确定记录产物确实足够。

第二阶段接入三个已记录波长通道。三波长预览应明确命名，不等同连续白光。

白光模式需要给定光源光谱及角尺寸，对模型支持的波长范围求解并积分。离散模式数按布拉格谱宽自适应细化；对窄谱峰做收敛检查，不能等间隔取几个颜色就断言准确。使用人眼 CIE 色匹配或明确选定的相机响应，再做显示转换；名义光源应标记，不能伪称实测。

目前等效对称 Kogelnik 模型不能保证任意倾角、倾斜/多重体光栅、任意重建谱和高 NA 下的准确性。应先给出支持的旋转/照明域，再逐步扩展验证。旋转时出现颜色变化、变暗或消失是可能结果，具体由记录决定，不能把“始终鲜艳可见”当验收要求。

## 7. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 黑背景＋单色干板＋匹配照明 | 不打开工程面板即可拖动干板观察重建；显示有效域和当前计算状态 |
| 关闭重建灯 | 无重建贡献；界面轮廓不计入光学能量 |
| 固定灯与眼，旋转干板 | 依据入射角及观察方向更新布拉格响应和可见像；记录内容哈希不变 |
| 固定灯与板，横向移动眼 | 深度测试样本产生正确方向和幅度的视差；记录不失效 |
| 两个不同深度的点/小图案 | 相机聚焦与视差符合独立传播基准，能够区分板前/板后位置 |
| 点在有限干板可见视域外 | 由口径与传播决定的遮挡/消失；不会无限显示源图像 |
| 白光角度/光谱扫描 | 布拉格峰、颜色与亮度对照独立参考；光谱积分加密收敛 |
| 保存、关闭原 Bench、移除原视图后打开 | 仅用记录产物仍能完成其声明能力内的重建 |
| 连续拖动和切换灯光 | 主线程响应；旧请求不能覆盖新结果，渐进累积不混入旧状态 |
| 超出模型范围或记录采样不足 | 可交互显示板姿态并解释限制，不输出冒充验证结果的特效 |

拟议性能场景命名为 `showroom/monochrome_two_depth_points` 与 `showroom/rgb_hogel_patch_8x8`，记录分辨率、瞳孔/光谱采样、硬件、驱动、内存和数值误差。初始产品预算可设：1920×1080 展示操作 p95 < 33.3 ms，停止拖动后的首个有效预览目标 < 250 ms；高质量耗时单独报告。这些是待测目标，不是当前性能声明；预览未满足精度时必须明确，不以延迟目标覆盖物理要求。

## 8. 与 CHIMERA 改进路线合并

展示间从单色独立记录产物开始，作为原评审 P2 的核心用户验收，与 P1 的简化工作台和机械改进衔接。P3 加入 RGB/光谱重建；P4 将小块打印结果接入同一观察模式。

实现时先做记录状态与观察状态解耦、单色观察求解，再接展示间交互与渐进 worker；最后加入光谱及多 hogel 优化。展示间不能以原始多视图贴图替代尚未实现的独立重建来提前关闭验收。
